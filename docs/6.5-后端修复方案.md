### 问题 1：登录/注册 404 问题

#### 根因分析

**现象**: 前端请求 `POST /api/auth/login` 和 `POST /api/auth/register` 返回 `500 Internal Server Error`，浏览器 DevTools 显示 404 是因为 nginx/代理层响应异常。

**真正根因**: 后端 uvicorn 进程使用了系统 Python 3.13（`/Library/Frameworks/Python.framework/Versions/3.13/bin/python3`），而非项目 venv 的 Python 3.11。系统 Python 3.13 的 `passlib` 与 `bcrypt` 存在兼容性问题：

```
(trapped) error reading bcrypt version
AttributeError: module 'bcrypt' has no attribute '__about__'
ValueError: password cannot be longer than 72 bytes
```

导致 `verify_password()` 和 `hash_password()` 抛出异常，auth 接口全部 500。

#### 修复方法

```bash
# 1. 杀掉旧进程
lsof -ti :8000 | xargs kill -9

# 2. 用 venv Python 重启
cd backend
nohup .venv/bin/python3 -m uvicorn src.main:app \
  --host 0.0.0.0 --port 8000 \
  > /tmp/moodwave-backend.log 2>&1 &
```

#### 验证结果

```bash
# 注册测试
curl -X POST http://localhost:8000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","username":"test","password":"test123"}'
# → 200 OK，返回 JWT token

# 登录测试
curl -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"test123"}'
# → 200 OK，返回 JWT token
```

#### 预防措施

建议在 `backend/` 目录添加 `start.sh` 脚本：

```bash
#!/bin/bash
cd "$(dirname "$0")"
source .venv/bin/activate
uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
```

避免混用系统 Python 和 venv Python。

### 问题 2：游客模式需提示登录

#### 现状

当前游客模式（未登录状态）：
- **Dashboard 首页**: 可以查看，使用本地 Zustand store 存储数据
- **其他功能页**: 直接发起请求 → 后端返回 401 → 前端无友好提示

#### 问题和影响

1. 所有后端 API 端点都使用 `Depends(get_current_user)` 进行鉴权
2. 游客点击情绪记录、音乐、分析、伙伴等功能时，后端直接返回 401
3. 前端没有统一的登录提示层，体验差

#### 修复方案

**方案**: 前端 API 拦截器 + 登录提示弹窗

##### 2.1 API 拦截层（`src/lib/api.ts`）

在 `apiClient` 的响应拦截器中，对 401 错误做统一处理：

```typescript
// 在 src/lib/api.ts 的 interceptors.response 中添加
apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      // 1. 检查是否在浏览器环境
      if (typeof window !== 'undefined') {
        // 2. 触发全局登录提示事件（不跳转页面）
        window.dispatchEvent(new CustomEvent('moodwave:login-required', {
          detail: { 
            message: '登录后即可使用此功能',
            returnUrl: window.location.pathname 
          }
        }))
      }
    }
    return Promise.reject(error)
  }
)
```

##### 2.2 登录提示组件（新建 `src/components/LoginPromptSheet.tsx`）

```tsx
// 监听 moodwave:login-required 事件，弹出底部 Sheet
// 内容：
// ✓ 一句友好的文案："登录后即可记录情绪、听治愈音乐 ✨"
// ✓ [去登录] 按钮 → 跳转 /login?returnUrl=当前页面
// ✓ [暂时不了] 按钮 → 关闭弹窗，留在当前页
// ✓ 不显示 X 关闭按钮（但 [暂时不了] 可关闭）
```

##### 2.3 在 `moodwave-shell.tsx` 中注册

```tsx
// 在 MoodWaveShell 组件中挂载 LoginPromptSheet
<>
  <LoginPromptSheet />
  {/* 现有布局 */}
</>
```

##### 2.4 涉及的功能点（需要 401 → 提示登录）

### 问题 4：音乐播放按钮无法暂停

#### 根因分析

播放/暂停功能为纯前端实现（Tone.js Web Audio API），不依赖后端。

通过代码审查发现 `togglePlay` 函数逻辑正确：

```typescript
function togglePlay() {
  if (isPlaying) {
    stopMusic()  // → Transport.stop() + disposeTone() + setIsPlaying(false)
  } else {
    void startMusic()  // → 重新初始化合成器 + Transport.start() + setIsPlaying(true)
  }
}
```

#### 可能的问题原因

1. **Tone.js 未完成加载**: `startMusic` 内部 `await import("tone/build/esm/index")` 是异步动态导入，如果 toneRef 为空且导入未完成，按钮会显示 loading 状态
2. **AudioContext 未激活**: Safari/iOS 要求用户手势才能激活 AudioContext，首次点击可能只激活了 AudioContext 而未启动播放
3. **状态竞态**: `startMusic` 是 async 函数，快速双击可能产生竞态条件

#### 修复方案

##### 4.1 添加防抖保护

```typescript
const [isTransitioning, setIsTransitioning] = useState(false)

function togglePlay() {
  if (isTransitioning) return  // 防止快速点击
  
  setIsTransitioning(true)
  if (isPlaying) {
    stopMusic()
    setIsTransitioning(false)
  } else {
    void startMusic().finally(() => setIsTransitioning(false))
  }
}
```

##### 4.2 修复 startMusic 中 AudioContext 激活

```typescript
const startMusic = useCallback(async () => {
  setIsLoading(true)
  try {
    const Tone = toneRef.current ?? (await import("tone/build/esm/index"))
    toneRef.current = Tone
    
    // 关键：确保 AudioContext 已激活
    await Tone.start()
    console.log("AudioContext state:", Tone.getContext().state)  // 调试用
    
    stopMusic()  // 清理旧状态
    
    // ... 创建合成器 ...
    
    // 确保 Transport 真正启动
    Tone.Transport.start()
    
    // 延迟确认播放状态（避免 AudioContext 未就绪）
    await new Promise(resolve => setTimeout(resolve, 100))
    if (Tone.getContext().state === 'running') {
      setIsPlaying(true)
    }
  } catch (err) {
    console.error("startMusic failed:", err)
    setIsPlaying(false)
  } finally {
    setIsLoading(false)
  }
}, [currentBpm, intensity, mood, profile, stopMusic])
```
