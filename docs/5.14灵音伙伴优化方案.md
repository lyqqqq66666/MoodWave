## 一、背景与目标

### 1.1 背景

灵音伙伴是 MoodWave 的核心交互功能，当前已有三个 Tab（对话/装扮/记忆），但功能较为基础：

- 对话：固定欢迎语，聊天记录仅存前端，刷新丢失
- 装扮：形象选择有限（5 个），配色未持久化
- 记忆：基于最近 30 条情绪记录即时生成，无独立记忆库

### 1.2 目标

基于现有架构（FastAPI + DeepSeek + Next.js），将灵音伙伴升级为：

```
情绪陪伴型 Agent = 动态欢迎语 + 丰富形象 + 会话持久化 + 长期记忆 + Agent 编排
```

比赛包装话术：

> MoodWave 灵音伙伴基于 FastAPI + DeepSeek + LangGraph 构建情绪陪伴型 AI Agent，通过状态图编排情绪识别、长期记忆检索、个性化共情回应、音乐疗愈推荐与记忆更新，实现从情绪输入到疗愈反馈的闭环陪伴体验。

### 2.2 存在问题

| 问题 | 影响 |

## 三、优化需求（P0-P3）

### 3.1 P0：体验明显变好

#### 3.1.1 动态欢迎语

**当前**：固定文案

**目标**：
- 当天有情绪记录 → 根据最新 MoodEntry 动态生成
- 当天无情绪记录 → 根据当前伙伴形象生成不同语气
- 不同伙伴语气明显不同

**新增接口**：
```
GET /api/companion/greeting
```

**返回示例**：
```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "greeting": "今天你记录了有点焦虑，小宇航员会陪你把事情拆小一点。",
    "starter_messages": [
      "要不要先告诉我，今天最让你紧绷的是哪一件事？",
      "我可以陪你一起把它拆成三个小步骤。"
    ],
    "source": "today_mood",
    "mood_type": "anxious",
    "character": "astronaut"
  }
}
```

#### 3.1.2 新增伙伴形象

**当前形象（5 个）**：小樱、小星球、阳光少年、小宇航员、月光伙伴

**新增形象（2 个）**：

|----|------|----------|----------|
| cat | 小喵 | 温柔撒娇 | 低落、睡前倾诉 |
| fox | 小狐狸 | 机灵鼓励 | 焦虑拆解、行动建议 |

**前后端统一 id**：`cat / fox / sakura / planet / sunny / astronaut / moon`

#### 3.1.3 对话区优化

- 明确可见的滚动条
- 「新建聊天」按钮
- 消息多时体验清晰

### 3.2 P1：Agent 数据基础

#### 3.2.1 会话/消息持久化

**新增数据表**：

```python
class CompanionConversation(SQLModel, table=True):
    id: Optional[int]
    user_id: int
    title: str                    # 会话标题（自动生成或用户命名）
    character: str                # 伙伴形象 id
    created_at: datetime
    updated_at: datetime

class CompanionMessage(SQLModel, table=True):
    id: Optional[int]
    conversation_id: int
    user_id: int
    role: str                     # user / assistant / system
    content: str
    mood_type: Optional[str]      # 关联情绪类型
    metadata: str                 # JSON 字符串（存储额外信息）
    created_at: datetime
```

**新增接口**：
```
POST   /api/companion/conversations              # 新建会话
GET    /api/companion/conversations              # 会话列表
GET    /api/companion/conversations/{id}/messages # 获取消息历史
POST   /api/companion/conversations/{id}/messages # 发送消息（流式返回+自动保存）
```

#### 3.2.2 上下文窗口控制

- 从数据库读取最近 N 条消息（建议 12 条 = 6 轮）
- 避免无限传历史导致 token 爆炸

#### 3.2.3 character_color 后端持久化

- 在 `users` 表新增 `character_color` 字段
- 装扮选择同步保存到后端

### 3.3 P2：记忆系统升级

#### 3.3.1 新增 CompanionMemory 表

```python
class CompanionMemory(SQLModel, table=True):
    id: Optional[int]
    user_id: int
    character: str                # 伙伴形象 id
    source_type: str              # mood_entry / conversation / mixed
    source_id: Optional[int]      # 来源记录 id
    memory_date: date             # 记忆日期
    mood_type: str                # 情绪类型
    title: str                    # 记忆标题
    summary: str                  # 摘要
    detail: str                   # 完整内容
    importance: int               # 重要性 1-5
    created_at: datetime
    updated_at: datetime
```

#### 3.3.2 记忆来源

- **情绪记录**：文字、标签、强度、情绪类型
- **对话内容**：用户与伙伴对话中的重要内容
- **混合来源**：综合情绪记录和对话

#### 3.3.3 记忆生成逻辑

1. 用户完成一轮对话后，异步调用 DeepSeek 提取记忆
2. 设置 importance 阈值（≥3 才保存）
3. 不同伙伴的记忆独立存储

#### 3.3.4 新增接口

```
GET    /api/companion/memories                    # 记忆列表（支持筛选）
GET    /api/companion/memories/{id}               # 记忆详情
POST   /api/companion/memories/generate           # 手动生成记忆
PATCH  /api/companion/memories/{id}               # 更新记忆
DELETE /api/companion/memories/{id}               # 删除记忆
```

## 七、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| **数据迁移** | 新表创建可能失败 | 先检查表是否存在，CREATE IF NOT EXISTS |
| **DeepSeek 超时** | 欢迎语/记忆生成卡住 | 设置 10s 超时，fallback 到本地模板 |
| **SSE 保存消息时机** | 流式响应中保存失败 | 流式结束后异步保存，不阻塞响应 |
| **角色 id 不一致** | 前后端数据对不上 | 后端统一用英文 id，前端做映射 |
| **记忆生成质量** | 生成无意义记忆 | 设置 importance 阈值（≥3 才保存） |
| **LangGraph 依赖冲突** | 安装失败影响现有功能 | 隔离测试，失败则退回普通服务层 |
| **SQLite JSON 查询慢** | 记忆筛选性能差 | 接口层过滤，数据量小可接受 |
| **会话数据膨胀** | 数据库文件过大 | 定期清理 30 天前的会话 |
