## 1. 优先级定义

## P0

必须先做。

特点：

- 直接影响用户第一印象
- 直接影响登录、录入、联调
- 不解决就会持续影响后续页面改版

## P1

核心优化项。

特点：

- 决定 Web 端是否真正完成“改版”
- 决定页面是否统一、治愈、可用

## P2

增强项。

特点：

- 不影响主链路打通
- 但会明显提升完成度和产品感

## 2. P0 清单

## P0-1 未登录首页首屏重构

### 目标

- 去掉旧版左右分栏重文字结构
- 去掉 `78.1%`、`今晚` 这类文案
- 首屏只保留一个主按钮 `开始体验`
- 右上角保留 `登录`
- 让首页变成“动态角色 + 一句说明 + 一个 CTA”的轻结构

### Codex 负责

- 重做 [frontend/src/app/page.tsx](/Users/LYQ/Desktop/大三资料/我的vibe-coding项目/情绪日记+可视化音乐项目/frontend/src/app/page.tsx)
- 清理旧首页重复按钮和旧文案
- 改成居中式 / 上下排布
- 预留动态宠物主视觉区域

### WorkBuddy 负责

- 无需主负责

### 验收标准

- 首页打开后第一屏不再出现旧调查文案
- 首屏只出现一个主 CTA
- 页面不再是强左右分栏

### 测试

- `390 / 768 / 1440` 断点检查
- 浏览器强刷检查是否还残留旧首页缓存

## P0-2 登录页 API 与视觉基础修正

### 目标

- 修正登录页请求地址问题
- 修正第三方登录图标
- 登录成功后有明确成功提示
- 邮箱输入框 placeholder 改成 `请输入邮箱地址`

### Codex 负责

- 登录页视觉修正
- 图标替换
- 登录成功提示 UI
- 输入框文案统一

### WorkBuddy 负责

- 注册 / 登录 / me 接口稳定
- token 返回正确
- 登录后跳转链路稳定

### 验收标准

- 登录不再出现相对路径 404
- 登录成功后有中上部成功提示
- 微信 / 苹果 / 谷歌图标正确

### 测试

- 注册
- 登录
- 登录失败提示
- 登录成功提示
- 登录后跳转

## P0-3 Web 端环境和缓存一致性修正

### 目标

- 防止“代码是新版，浏览器还是旧页面”
- 防止不同 worktree / 分支 / `.env` 配置混用

### Codex 负责

- 统一检查 `next.config.js`
- 统一检查 `.env.local`
- 统一说明前端应从哪个 worktree 启动

### WorkBuddy 负责

- 无需主负责

### 验收标准

- 当前运行中的前端明确使用正确环境变量
- 浏览器打开的是新版页面

### 测试

- 启动日志确认 `.env.local`
- 首页 HTML 内容检查
- 强刷与新端口验证

## P0-4 情绪录入页信息结构重排

### 目标

- 先解决“五步太碎、顺序不顺、日期不清”的主问题
- 不要求第一轮就做满所有细节，但要先把结构理顺

### Codex 负责

- 重构 [frontend/src/app/mood/page.tsx](/Users/LYQ/Desktop/大三资料/我的vibe-coding项目/情绪日记+可视化音乐项目/frontend/src/app/mood/page.tsx)
- 调整标签位置
- 减少强 `下一步` 依赖
- 优化日期区结构与说明文案
- 优化输入框 placeholder

### WorkBuddy 负责

- 保证 moods / analyze / upload voice 基本链路通

### 验收标准

- 标签不再是最后才出现的割裂步骤
- 用户能清楚知道记录的是哪一天
- 流程点击次数明显减少

### 测试

- 当天记录
- 补记记录
- 文字输入
- 不输入标签也能正常提交

## P0-5 AI 分析真实性与语音转写感知修正

### 目标

- 让用户感知到“这次真的是 AI 在处理”
- 让语音转写结果真正可见

### Codex 负责

- 优化分析中的 loading / processing 状态
- 优化语音转写展示层级
- 优化 fallback 时前端文案

### WorkBuddy 负责

- 检查语音转写是否真实返回
- 检查 AI analyze 是否真实调用
- 收敛 fallback 策略

### 验收标准

- 录音后可明显看到转写结果或识别状态
- AI 分析时不再像“秒出模板”

### 测试

- 纯文本分析
- 文本 + 图片
- 文本 + 语音
- AI 超时 / 降级场景

## 5. 测试与验收流程

## 5.1 每个优先级阶段完成后必须做的测试

- 前端 `lint`
- 前端 `type-check`
- 后端基础检查
- 浏览器人工回归
- 登录态 / 游客态 / 异常态检查

## 5.2 推荐脚本

- `sh scripts/check-frontend.sh`
- `sh scripts/check-backend.sh`
- `sh scripts/review-web-phase.sh`

## 5.3 重点人工回归项

- 首页是否还是旧版
- 登录是否还打到相对路径 `/api/...`
- 补记日期是否明显
- 录音后是否可见转写
- AI 分析是否仍像模板
- 音乐页是否仍像普通播放器

## 7. Code Review 清单

提交前必须检查：

- 是否真的减少了页面信息密度
- 是否去掉了不必要的重复按钮
- 是否仍残留旧版首页文案
- 是否仍有技术型报错文案直接暴露给用户
- 是否仍存在“强制多步骤点击”
- 是否角色体系又混回多套风格
- 是否音乐页又变回普通播放器感

---
