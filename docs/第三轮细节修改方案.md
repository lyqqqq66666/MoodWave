## 问题 1：移动端个人设置页布局溢出 + 导出功能不完善

### 影响页面

`/profile` — 个人主页的设置菜单

### 1A：设置菜单左侧遮挡问题

#### 根因诊断

当前设置菜单 (`profile/page.tsx:261`)：

```html
<div class="absolute right-0 top-12 z-40 w-[min(340px,calc(100vw-2rem))] ...">
```

**问题分析**：
- 设置菜单采用 `absolute right-0` 定位，在移动端（屏幕宽度 ≤ 390px）时，菜单宽度 `calc(100vw-2rem)` ≈ 358px，配合 `right-0` 导致左侧边缘紧贴屏幕边缘，部分内容被刘海/圆角裁剪
- 设置项使用 `gap-2` 垂直排列，按钮内 `flex items-center gap-3` 布局，在窄屏下图标 + 文字 + 箭头容易换行或溢出
- 导出弹窗 (`showExportDialog`) 的 modal 用了 `w-full max-w-md`，在移动端弹窗内 export 格式下拉和"导出并下载"按钮可能超出可视区域
- 设置菜单是浮层弹出方式（非页面级），在小屏设备上点按区域过小，容易误触

#### 修改方案

| # | 改动 | 文件 | 负责 |
|---|------|------|:---:|
| 1.1 | 设置菜单改为**全屏/半屏 Bottom Sheet** 模式：移动端从底部滑出（`fixed bottom-0 inset-x-0`，占屏幕 70% 高度），桌面端保持现有浮层 | `frontend/src/app/profile/page.tsx` | Codex |
| 1.2 | Bottom Sheet 内部内容区域 `overflow-y-auto` 独立滚动，顶部加拖拽手柄（drag handle），底部留 safe-area-inset-bottom | `frontend/src/app/profile/page.tsx` | Codex |
| 1.3 | 导出弹窗也改为移动端 Bottom Sheet / 桌面端 Modal 响应式适配，确保"导出并下载"按钮在移动端可见 | `frontend/src/app/profile/page.tsx` | Codex |
| 1.4 | 设置项间距优化：`gap-2` → `gap-2.5`，按钮最小高度 `min-h-[52px]` 增加触控面积 | `frontend/src/app/profile/page.tsx` | Codex |

### 1B：导出功能完善

#### 根因诊断

当前导出 (`profile/page.tsx:201-244`)：

```typescript
// 前端本地导出
function exportLocalData(format: "json" | "csv") {
  const rows = records.map((record) => ({
    id, date, mood, tag, title, note
  }))
  // 仅导出当前页面加载的情绪记录
}

// 后端导出
async function exportProfileData(format: "json" | "csv") {
  const response = await profileAPI.export(format)
  // GET /api/profile/export?format=json|csv
}
```

**问题分析**：
- 后端 `/api/profile/export` 接口尚未实现（`profileAPI.export` 调用但路由未注册在 `main.py` 中）
- 前端本地导出仅包含 `records`（当前页面加载的记录），缺少：
  - **情绪分析汇总数据**（`summary` — 主导情绪、高频标签、情绪趋势）
  - **用户个人资料**（昵称、MBTI、星座、头像 URL）
  - **收藏音乐列表**（`favoriteMusic`）
  - **心境清单**（`checklistItems`）
  - **完整历史记录**（后端数据库中的全量数据，而非前端的 30 天窗口）
- CSV 导出未处理中文乱码（缺 BOM 头）
- 导出弹窗中"范围"下拉被 `disabled` 写死为"全部"，无法选择时间范围

#### 建议导出的数据维度

| 数据类别 | 包含字段 | 来源 | 优先级 |
|----------|----------|------|:---:|
| **情绪记录** | id, date, mood_type, intensity, tags, note, images_urls, voice_url, voice_text, is_shared, created_at | `mood_entries` 表 | 🔴 核心 |
| **情绪分析汇总** | dominant_mood, mood_distribution (饼图数据), mood_trend (30天折线数据), top_tags, total_entries | `analytics/summary` 接口 | 🔴 核心 |
| **用户个人资料** | username, email, mbti, zodiac, character_color, avatar_character, created_at | `users` 表 | 🟡 推荐 |
| **收藏音乐** | music_id, title, artist, mood_type, favorited_at | `favorites` 表 | 🟡 推荐 |
| **心境清单** | item_text, mood_tag, done, created_at | 当前纯前端存储 → 需先入库 | 🟢 可选（后期） |
| **AI 对话历史** | timestamp, role, message_content | 按需 | 🟢 可选（后期） |

#### 修改方案

| # | 改动 | 文件 | 负责 |

## 问题 2：可视化音乐进度条无拖动功能 + 分享功能提示

### 影响页面

`/music` — 治愈音乐页面

### 2A：进度条不支持拖动/点击跳转

#### 根因诊断

当前进度条 (`music/page.tsx:727-738`)：

```html
<div class="h-2 rounded-full bg-[#f0edf0]">
  <motion.div
    animate={{ width: `${progress}%` }}
    class="h-full rounded-full bg-gradient-to-r from-[#ff8fa3] to-[#8de1d5]"
  />
</div>
```

**问题分析**：
- 进度条是纯视觉展示，`<motion.div>` 没有绑定任何交互事件（`onClick`、`onDrag`、`onTouchStart/Move/End`）
- 没有可拖动的滑块（thumb/knob），用户无法直观感知可交互
- 移动端需要支持 `touch` 事件，桌面端需要支持 `mouse` 事件
- 需要关联到 Tone.js 的播放进度，实现 `seekTo(percent)` 功能

#### 修改方案

| # | 改动 | 文件 | 负责 |
|---|------|------|:---:|
| 2.1 | 进度条改为可交互组件：
  - 增加圆形滑块（thumb），跟随进度移动
  - 绑定 `onMouseDown` / `onMouseMove` / `onMouseUp`（桌面端）和 `onTouchStart` / `onTouchMove` / `onTouchEnd`（移动端）
  - 点击/拖动时计算百分比 → 调用 `seekTo(percent)` 方法
  - 拖动时暂停进度动画，松手后恢复 | `frontend/src/app/music/page.tsx` | Codex |
| 2.2 | 实现 `seekTo(percent: number)` 方法：
  - 计算目标时间 `targetTime = totalDuration * percent`
  - 更新 `elapsedTime` 状态
  - 如果使用 Tone.js Transport，调用 `Tone.Transport.seconds = targetTime`
  - 如果是模拟播放（纯前端计时），重置计时器起点 | `frontend/src/app/music/page.tsx` | Codex |
| 2.3 | 触摸/鼠标交互细节：
  - 拖拽时滑块放大（`scale-125`）+ 进度条加粗（`h-2 → h-3`）
  - 显示悬浮时间标签（如 "1:23 / 3:45"）
  - 触控区域扩大（进度条上下各扩展 12px 的透明 touch-target） | `frontend/src/app/music/page.tsx` | Codex |
| 2.4 | 跨度保护：拖动范围限制在 0-100%，边界不回弹 | `frontend/src/app/music/page.tsx` | Codex |

## 问题 4：移动端语音输入无浏览器权限

### 影响页面

`/mood` — 情绪录入页 Step 3「内容」→ 语音录制组件

### 根因诊断

当前实现 (`mood-voice-recorder.tsx:28-61`)：

```typescript
async function startRecording() {
  try {
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true })
    // ...
  } catch {
    setNotice("浏览器没有开启麦克风权限，可以先用文字记录。")
  }
}
```

**问题分析**：

`getUserMedia()` 的安全限制：

| 条件 | 结果 |
|------|------|
| HTTPS 页面 | ✅ 正常获取权限 |
| `localhost` | ✅ 视为安全上下文 |
| HTTP 页面（生产环境） | ❌ 直接拒绝，不弹出权限弹窗 |
| iOS Safari（HTTP） | ❌ 拒绝 + 无提示 |
| 微信内置浏览器（HTTP） | ❌ 大部分版本拒绝 |
| 用户手动拒绝过权限 | ❌ `NotAllowedError` |
| 设备无麦克风 | ❌ `NotFoundError` |

**当前生产环境**：
- 前端部署在 Vercel（HTTPS → ✅ 安全上下文）
- 后端在腾讯云 `106.52.8.176:8000`（HTTP → 但 `getUserMedia` 只看页面协议）
- 如果用户通过 HTTP 访问（直连 IP:3002）→ 会被浏览器拒绝

**但核心问题是**：即使用 HTTPS，移动端（尤其是 iOS Safari）还需要用户**主动点击**触发才能弹出权限弹窗（要求 `getUserMedia` 在用户手势事件中调用），且一旦拒绝后需要引导用户去**系统设置**中手动开启。

当前代码虽然是在 `onClick` 中调用，但 catch 的错误提示太笼统（不区分错误类型）。

#### 修改方案

| # | 改动 | 文件 | 负责 |
|---|------|------|:---:|
| 4.1 | 细化错误处理：区分 `NotAllowedError`（用户拒绝）、`NotFoundError`（无设备）、`SecurityError`（非安全上下文）、其他错误 + 针对每种错误给不同引导文案 | `frontend/src/components/mood-voice-recorder.tsx` | Codex |
| 4.2 | `NotAllowedError` 处理（最关键）：
  - 提示文案："麦克风权限未开启，请在浏览器设置中允许麦克风访问。"
  - iOS Safari 用户额外显示引导："前往 设置 > Safari > 麦克风 > 允许"
  - 提供一个"去设置"按钮（仅提示，无法直接跳转系统设置） | `frontend/src/components/mood-voice-recorder.tsx` | Codex |
| 4.3 | `SecurityError` 处理（非 HTTPS 访问）：
  - 提示文案："语音录制需要安全连接（HTTPS），请使用 https:// 开头的地址访问。"
  - 检测 `window.location.protocol === 'http:'` 且非 localhost 时，显示此提示 | `frontend/src/components/mood-voice-recorder.tsx` | Codex |
| 4.4 | 增加**权限预检测**：在组件挂载时调用 `navigator.permissions.query({ name: 'microphone' })`（如果支持）提前检查权限状态，显示对应的状态标签（"麦克风已就绪" / "需要授权"） | `frontend/src/components/mood-voice-recorder.tsx` | Codex |
| 4.5 | iOS Safari 兼容：确保 `getUserMedia` 在 `onClick` 事件处理中**同步**调用（当前已是），同时添加 `playsinline` 相关处理 | `frontend/src/components/mood-voice-recorder.tsx` | Codex |
| 4.6 | 兜底方案：语音录制失败时，引导用户使用"文字输入"替代；在 Step 3 页面显示一条永久可见的提示："语音功能需要麦克风权限，你也可以直接用文字记录。录制后会自动转为文字。" | `frontend/src/app/mood/page.tsx` | Codex |
| 4.7 | 后端验证：确认上传接口 `POST /api/upload/voice` 正常工作（支持 webm/ogg 格式），并确认语音转文字服务（Whisper 或其他）可用 | `backend/src/routers/upload.py` | WorkBuddy |

## 关键注意事项

1. **导出接口幂等性**：GET `/api/profile/export` 需要 JWT 认证，从 token 解析 user_id
2. **语音格式兼容**：确认后端接收 `audio/webm`（Chrome/Firefox）和 `audio/mp4`（Safari）格式
