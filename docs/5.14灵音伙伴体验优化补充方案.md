# 灵音伙伴体验优化补充方案

> 日期：2026-05-14  
> 目的：在 P0-P3 Agent 能力完成后，优化「灵音伙伴」页面的信息架构与真实用户体验。  
> 面向：WorkBuddy 先做分工计划，再按后端/前端拆任务执行。

---

## 一、为什么需要补充优化

当前灵音伙伴已经完成：

- P0 动态欢迎语
- P1 会话/消息持久化
- P2 记忆系统
- P3 LangGraph Agent 编排

但当前页面存在体验问题：

1. Agent 工作流直接大面积展示，普通用户不应该默认看到 `load_profile → load_mood → ...` 这种工程细节。
2. Agent 状态面板和音乐推荐卡片占据聊天区顶部，导致真正的聊天内容和输入框被挤压。
3. 最近会话横向卡片放在主聊天区域里，使对话框变小。
4. 历史会话与长期记忆的概念容易混淆。
5. 历史会话缺少删除、改标题等管理能力。
6. 对话消息没有显示发送时间，用户无法知道每条消息发生在什么时候。

核心原则：

> 用户看到的是「自然聊天体验」；评委需要时才展开「Agent 技术过程」。

## 二、概念区分：历史会话 vs 长期记忆

### 2.1 历史会话 Conversation

历史会话是用户和灵音伙伴的一段聊天记录。

特点：

- 面向「回看聊天」
- 由 `CompanionConversation` + `CompanionMessage` 组成
- 每条消息有 role、content、created_at
- 用户可以新建、切换、删除、修改标题
- 类似 ChatGPT 左侧历史记录

用户理解文案建议：

- 「历史对话」
- 「最近聊天」
- 「这段聊天」

不要叫「记忆」。

### 2.2 长期记忆 Memory

长期记忆是灵音伙伴从情绪记录和对话中提炼出的稳定线索。

特点：

- 面向「伙伴理解用户」
- 由 `CompanionMemory` 表保存
- 内容是摘要/观察，不是完整聊天原文
- 可以按类型筛选：性格线索、偏好、习惯、事件
- 可以点击查看详情、删除

用户理解文案建议：

- 「伙伴记住的小线索」
- 「长期记忆」
- 「灵音观察」

不要叫「聊天记录」。

## 三、页面信息架构调整

### 3.1 对话 Tab 新结构

当前结构里最近会话、Agent 工作流、音乐推荐都堆在聊天区顶部，建议调整为：

```text
对话 Tab
├── 顶部工具栏
│   ├── 当前会话标题
│   ├── 历史按钮
│   ├── 重命名按钮
│   ├── 删除按钮
│   └── 新建聊天按钮
├── 聊天消息滚动区
│   ├── 用户消息 + 时间
│   ├── 伙伴消息 + 时间
│   ├── 音乐推荐小卡片（跟随某次回复）
│   └── Agent 简短状态（仅运行时）
└── 输入框
```

重点：

- 聊天消息区必须是主角，占据最大高度。
- 最近会话不要常驻占用聊天高度。
- Agent 工作流不要默认展开。
- 音乐推荐放在消息流里，跟着对应回复出现。

### 3.2 历史会话入口

建议改为右上角按钮：

```text
[历史] [新建聊天]
```

点击「历史」后显示抽屉或浮层：

```text
历史对话
├── 搜索/筛选（可选）
├── 会话 A
│   ├── 标题
│   ├── 更新时间
│   ├── 消息数量
│   ├── 重命名
│   └── 删除
├── 会话 B
└── ...
```

第一阶段可以做轻量浮层，不必做复杂侧边栏。

### 3.3 Agent 工作流展示

普通用户默认只看到自然语言状态：

```text
灵音正在理解你...
```

Agent 节点链路默认收起：

```text
[查看 Agent 过程]
```

点击后再展示：

```text
load_profile → load_mood → load_memories → classify_emotion → ...
```

比赛演示时可以展开这个过程，但普通用户不默认看到。

### 3.4 音乐推荐卡片

音乐推荐应该跟随 AI 回复，而不是放在对话区顶部大块占位。

建议作为 AI 回复后的消息内卡片：

```text
灵音回复：
我听见你现在有点低落...

🎵 灵音推荐音乐
低落 · BPM 65 · classical
钢琴独奏 + 雨声背景
[进入音乐房间]
```

后续如果音乐页支持参数跳转，可加：

```text
/music?mood=sad&bpm=65&style=classical
```

## 四、必须新增/完善的功能

### 4.1 历史会话管理

用户需要能：

- 查看历史会话
- 切换历史会话
- 新建聊天
- 删除历史会话
- 修改会话标题

当前已有：

- `POST /api/companion/conversations`
- `GET /api/companion/conversations`
- `GET /api/companion/conversations/{id}/messages`
- `DELETE /api/companion/conversations/{id}`

缺少：

```text
PATCH /api/companion/conversations/{id}
```

用于修改会话标题。

建议请求：

```json
{
  "title": "有推荐的音乐"
}
```

建议返回：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": 1,
    "title": "有推荐的音乐",
    "updated_at": "2026-05-14T18:00:00"
  }
}
```

### 4.2 消息显示时间

对话框里每条消息都要显示当前时间。

用户消息：

```text
我：有没有推荐的音乐
18:26
```

伙伴消息：

```text
灵音：我给你推荐一段舒缓的音乐...
18:26
```

前端要求：

- 后端历史消息已有 `created_at`，加载历史时直接展示。
- 新发送的本地 optimistic message 用 `new Date().toISOString()` 作为临时时间。
- Agent 回复完成时，如果后端暂时不返回 assistant message id/time，前端可先用完成时间展示。
- 切换历史会话后，用后端 `created_at` 替换临时时间。

建议前端 `ChatMessage` 类型升级：

```ts
type ChatMessage = {
  id: string
  role: "assistant" | "user"
  content: string
  created_at?: string
  music_recommendation?: AgentMusicRecommendation
}
```

### 4.3 音乐推荐绑定到消息

当前音乐推荐是页面级状态 `agentMusic`，导致它悬浮在消息区上方。

建议改为绑定到对应 assistant message：

```ts
setMessages(current =>
  current.map(item =>
    item.id === assistantId
      ? { ...item, music_recommendation: musicPayload }
      : item
  )
)
```

这样音乐卡片跟着某一条 AI 回复展示。

### 4.4 Agent 状态轻量化

当前页面级 `agentStatuses` 不适合常驻展示。

建议改为：

```ts
agentStatusSummary: "灵音正在理解你..."
agentDebugOpen: false
agentNodesExecuted: [...]
```

展示策略：

- 流式运行中：显示一行轻状态。
- 完成后：轻状态消失或显示「灵音已完成回应」。
- 节点详情只在用户点击「查看过程」后显示。

## 五、后端任务建议给 WorkBuddy

### 5.1 新增修改会话标题接口

新增：

```text
PATCH /api/companion/conversations/{conversation_id}
```

功能：

- 验证会话属于当前用户
- 更新 `title`
- 更新 `updated_at`
- 返回更新后的会话信息

建议模型：

```python
class ConversationUpdate(BaseModel):
    title: str
```

注意：

- 标题建议限制长度，例如 1-40 字。
- 空标题不允许。
- 返回格式保持 `{ code, msg, data }`。

### 5.2 确认删除会话接口可用

已有：

```text
DELETE /api/companion/conversations/{id}
```

请确认：

- 会删除该会话所有 `CompanionMessage`
- 删除后不会影响 `CompanionMemory`
- 删除不存在或非本人会话时返回明确错误

### 5.3 可选：Agent done 返回消息时间

目前前端可以用本地时间兜底。

如果后端愿意增强，可在 `done.content` 里返回：

```json
{
  "assistant_message_id": 123,
  "assistant_created_at": "2026-05-14T18:00:00"
}
```

这不是必需，但更利于前端精确展示。

## 六、前端任务建议给 Codex

### 6.1 重构对话 Tab 布局

目标：

- 聊天消息区变大。
- 历史会话不再占主聊天高度。
- Agent 工作流不再默认大面积展示。

任务：

- 把最近会话横向卡片改成「历史」按钮 + 浮层/抽屉。
- 顶部工具栏展示当前会话标题。
- 工具栏按钮：
  - 历史
  - 重命名
  - 删除
  - 新建聊天

### 6.2 历史会话浮层

功能：

- 展示会话列表。
- 点击切换。
- 支持删除。
- 支持重命名。
- 删除当前会话后，自动切换到最近一条会话或回到新会话状态。

### 6.3 消息时间

功能：

- 用户消息显示发送时间。
- 伙伴消息显示回复时间。
- 历史消息使用后端 `created_at`。
- 新消息使用本地临时时间。

### 6.4 Agent 状态折叠

功能：

- 默认只显示一行状态。
- 完成后隐藏或变成「Agent 已完成」。
- `查看过程` 按钮控制展开节点详情。
- 展开后再显示 `nodes_executed`。

### 6.5 音乐推荐卡片内联

功能：

- `music` SSE 事件绑定到当前 assistant message。
- 卡片显示在对应 AI 回复下面。
- 后续可接「进入音乐房间」按钮。
